# 内容格式规范

每部作品的 `content/` 目录是唯一内容源，`build.py` 将其解析为 `data.js`。本规范与 `build.py` 的解析逻辑一一对应，写作时请严格遵守，否则字段会被静默丢弃。

## 通用规则

- 文件编码 UTF-8，换行 LF。
- 每个文件以 `# 标题` 开头。
- 标题之后、`## ` 之前是**元信息区**，每行一条 `- 键: 值`（中文冒号 `：` 也可）。
- 正文按 `## 区块名` 切分；区块名必须完全匹配下表（如 `剧情`、`关键场景`、`背景`）。
- 段落之间用空行分隔；同一段内的单个换行会被合并。
- 列表项用 `- ` 或 `* ` 开头。
- 不确定的细节用「（待核）」标注，不要编造人名、数字或任务名；对话一律为**剧情要点整理，非逐字台词**。

## 一、主线章节 `content/10-story/*.md`

文件名建议 `ID-标题.md`，例如 `s1-01-雪原与贝洛伯格.md`。

```markdown
# 章节标题

- ID: s1-01            # 必填，路由与交叉引用用，全作品唯一
- 季: 雅利洛-VI         # 篇章分组标签（viewer 按此分组排序）
- 排序: 2              # 数字，同一作品内全局递增，决定章节顺序
- 版本: 1.0
- 阵营: 星穹列车, 银鬃铁卫   # 逗号 / 顿号分隔
- 一句话: 本章的一句话概括。

## 剧情

第一段……

第二段……

## 关键场景

### 场景名

**角色**：台词要点。

**另一角色**：台词要点。

【旁白】需要纯叙述时用「【旁白】」开头，或以「【...】」整行包裹。

## 名台词

- **角色**：「……」
- **角色**：「……」

## 伏笔

- ……
- ……

## 来源

- [名称](https://example.com/)
```

解析说明：
- `排序` 决定顺序；`季` 相同的章节会归为一组，组间按 `data.js` 中首次出现顺序排列。
- `关键场景` 里以 `**名字**：` 或 `名字：` 开头的行解析为对白；含 `http` 的行不会误判为对白。
- `来源` 只提取 Markdown 链接 `(url)` 或以 `http` 开头的地址。

## 二、角色 `content/20-characters/*.md`

文件名建议 `英文小写id.md`，例如 `jingyuan.md`。

```markdown
# 角色中文名

- ID: jingyuan
- 英文: Jing Yuan
- 阵营: 仙舟·罗浮
- 定位: 神策将军
- 初登场: 仙舟·罗浮
- 关键词: 将军, 智谋, 云上五骁
- 一句话: 一句话人物印象。

## 背景

一到两段背景……

## 关系

- **对象**：关系描述。
- **对象**：关系描述。

## 台词

- **角色**：「……」
```

## 三、时间线 `content/01-timeline.md`

每个 `## 事件名` 即一个事件；事件内用固定的四个元信息键，其余正文为描述。

```markdown
# 作品 时间线

## 事件名

- 时代: 开拓之旅
- 日期: 约……（可用「不明」等宽松表述）
- 章节: 雅利洛-VI
- 次要: false        # true / 是 / 1 视为次要事件

事件描述正文……
```

## 四、世界观 `content/00-worldview.md`

每个 `## 词条名` 即一个词条，正文 1–2 段。

```markdown
# 作品 世界观词条

## 词条名

词条解释……

## 另一个词条

……
```

## 构建与自检

```bash
cd <作品目录>
python3 build.py     # 重新生成 data.js
node --check data.js # 校验产物语法
```

`build.py` 会输出章节 / 角色 / 时间线 / 世界观数量与对话行数；若某章缺少 `## 剧情` 正文，会打印 `WARNING chapters without summary`。
